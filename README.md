## 项目简介

**《大都会：咆哮时代》** 是一款以 20 世纪初纽约曼哈顿为背景的单人回合制地产经营原型。玩家在有限回合中购买土地、建设资产、管理现金与债务，并在银行、股票、拍卖和新闻事件构成的城市市场里寻找扩张机会。

我长期喜欢地产经营题材，因为它天然适合把“空间位置”“现金流”“风险判断”和“长期回报”放在同一张桌面上。这个项目也是我以独立开发者身份完成的一次练习：不是先做一个漂亮页面，再往里面塞规则；而是先确定玩家每回合为什么做选择，再让地图、界面、文本和素材都服务于这个选择。

当前版本是浏览器可玩的原型。它仍处在美术与系统继续打磨的阶段，正式建筑、角色、音频和更完整的界面资产尚未全部完成；但核心目标已经清楚：把一个历史题材的地产经营创意，推进成可以试玩、可以验收、可以继续扩展的游戏项目。

## 我如何组织这个项目

### 从题材到可玩的回合

项目最初的核心不是“还原纽约”，而是让玩家读懂一座城市如何产生价值。曼哈顿被拆成 12 个街区、30 个可购买地块和 52 个历史地标；地块价格、产权、建筑、现金、债务和行动点共同决定玩家每回合的取舍。

我把单局压缩到 30 回合，让试玩者能在较短时间内经历扩张、借贷、建设、收益和结算。这样做的目的不是缩小游戏，而是让原型更快暴露问题：钱从哪里来、风险在哪里积累、每次点击是否真的改变局面。

### 让金融模块服务地产主线

我希望银行、股票、拍卖和新闻不是菜单装饰，而是围绕地产决策展开的四个压力来源。

| 模块 | 在原型中的作用 |
|---|---|
| Bank | 提供借款、还款和债务压力，让扩张不只是“有钱就买” |
| Stock Market | 提供短期流动性和市场波动，但不能压过地产经营本身 |
| Auction House | 让关键地块通过竞争进入市场，而不是全部静态出售 |
| News | 把经济变化、政策信号和交易反馈放进玩家能读懂的城市叙事 |

这些系统还没有全部达到最终状态，但它们已经定义了项目后续扩展的方向：每个模块都要回到土地、现金流和风险管理，而不是成为孤立小游戏。

### 把旧地图气质变成界面标准

视觉方向来自早期纽约 pictorial map、旧报纸、地产档案、证券票据和 Art Deco 装饰。地图不是背景图，而是主要操作面：玩家要在上面拖拽、缩放、点击街区、地块和历史地标。

因此我给视觉层设定了几条约束：旧地图纸色、深墨线条、暖橙水域、克制红色强调；历史地标要帮助识别城市，而不能遮挡地块；地图标签和交互反馈要优先保证可读性。现阶段美术素材仍在开发中，所以 README 里的截图也保留原型状态，而不是把它伪装成最终成品。

### 把外部执行变成可验收任务

这个项目使用 Vibe Coding，但我希望展示的不是“让 AI 替我做”，而是我如何把它纳入一个可控流程：先写产品目标和规则边界，再拆出阶段任务、允许修改的文件、停止条件和测试标准；实现之后再根据截图和试玩反馈逐项修正。

项目文档中保留了协作边界、阶段计划、验收清单、视觉规范、地图素材管线和开发日志。它们记录了很多具体取舍，例如：历史地标标签过小后改为隐藏；地标选中红光不能出现白底矩形；地图拖动和点击卡顿要从渲染层优化；系统原生弹窗要替换成游戏内弹窗。这些小问题看似琐碎，但正是项目推进中最真实的管理工作。

## 当前阶段

项目现在是一个可在线试玩的网页原型。Godot 工程保留在仓库中，作为后续正式游戏化的准备；当前主要验证地图操作、经济循环、界面组织、内容管线和项目推进方法。

下一阶段会继续完善：

- 拍卖流程与新闻事件的完整闭环
- 银行和股票市场的数值平衡
- AI 对手的差异化行为
- 更成熟的游戏内弹窗与 UI 资产
- 正式建筑、角色和音频素材

## 一句话总结

《大都会：咆哮时代》不是一张复古地图，也不是一组孤立功能。它是我把一个喜欢的地产经营题材，拆成规则、界面、素材、文档和交付节奏之后，逐步收束成可玩原型的项目。
