# 技术架构

## 原则

- Godot 场景负责呈现与输入，领域逻辑负责规则与结算，配置数据负责内容。
- 核心规则不依赖具体 UI 节点，便于自动化测试。
- 回合推进使用明确状态机，避免由多个界面节点分别修改全局状态。

## 建议模块

- `game_state`：回合数、指标、区域状态、历史记录。
- `turn_controller`：回合阶段与合法状态转换。
- `decree_service`：法令条件检查、效果计算与提交。
- `content_repository`：载入法令、区域和数值配置。
- `map_view`：区域交互及状态可视化。
- `hud` / `decree_panel` / `result_screen`：界面呈现。

## 数据与可测性

- 所有内容项使用稳定 ID，显示文本与逻辑引用分离。
- 一次行动产生结构化结算结果，供状态更新、动画和日志共同使用。
- 核心流程应能在无渲染环境中验证 20 回合、条件判定和重复提交防护。
