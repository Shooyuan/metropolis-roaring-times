## 三、老板现在需要交付什么

老板在 Figma 中建立任意尺寸、北向朝上的矢量画布；尺寸不影响游戏缩放，也不作为交付门槛。为了减少手工工作，只需：

1. 使用 `File → Save local copy…` 保存一份版本化 `.fig`。
2. 选中主画框并运行项目插件 `Metropolis Handoff Exporter`；如果当前八个地图顶层图层是并列 Group，则选中其中任意一层，插件会按实际矢量边界自动使用虚拟主画框。
3. 点击“一键导出 ZIP”。
4. 把 `.fig` 和 ZIP 交给 Codex。

插件自动保存图层、位置、颜色、矢量和原始图片。默认“大地图快速交付”生成网页实际使用的纯底图、街区与可购买地块 SVG，并把历史地标按父组拆成多份局部 SVG，由 `handoff/landmarks.json` 保存其准确位置；它跳过容易卡住的地标总图、整图、对齐合成、逐层重复文件和 PNG。需要完整重型结构和历史地标总图时才切换完整模式。若 Brand 不在地图文件中，则以独立 `assets/00_BRAND.svg` 交付。安装说明在 `tools/figma_handoff_exporter/README.md`。如果地图交付不完整，Codex 只报告问题，不修改老板源文件。

## 五、每个阶段固定管理流程

以后每个阶段必须按相同顺序：

1. **开始前报告**：Codex说明本阶段做什么、不做什么、输入、风险和需要老板决定的事项。
2. **老板批准**：只有明确批准当前范围后才开工。
3. **执行中报告风险**：遇到缺文件、规格冲突、越权风险或测试失败立即告诉老板。
4. **完成实现**：只完成当前阶段，不提前铺下一阶段。
5. **运行测试并修错**：失败不能用解释代替通过。
6. **提交老板验收**：视觉、故事或规则需要老板判断时，先展示证据，不自行判定通过。
7. **保存并提交 Git**：老板需要审批的门通过后，创建一个可恢复的 Git 提交。
8. **阶段报告**：列出文件、测试、提交号、剩余风险和下一阶段。
9. **再次等待批准**：不得把“继续讨论”自动理解成批准新的范围或视觉决定。
